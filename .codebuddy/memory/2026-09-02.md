# 2026-09-02

## xlsx (SheetJS) 升级到 0.20.3
- 原 `npm install` 报 1 个 high 漏洞：`xlsx@0.18.5` 的 Prototype Pollution（GHSA-4r6h-8v6p-xvw6 / CVE-2024-22363）。npm registry 上的 `xlsx` 永远停在 0.18.5（SheetJS 已不再向 npm 发布），`npm audit fix` 无解。
- 本环境 npm 禁止远程拉包（`EALLOWREMOTE`：安装 `xlsx@https://cdn.sheetjs.com/...tgz` 被拒）。解决方式：**用 PowerShell `Invoke-WebRequest` 下载 `xlsx-0.20.3.tgz` 到仓库根目录，再 `npm install ./xlsx-0.20.3.tgz`**。
- 结果：`npm audit` → `found 0 vulnerabilities`。
- 依赖形式演变：先是用本地 tarball `file:xlsx-0.20.3.tgz`（绕过 EALLOWREMOTE），后又按用户要求改为官方 CDN 形式 `"xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"`，并删除了仓库根目录的本地 tarball。
- 注意：本环境 npm 禁止远程拉包（`EALLOWREMOTE`），所以在本机执行 `npm install` 拉 CDN tarball 会失败；该 CDN 形式适用于允许远程拉包的环境。`node_modules` 里已是 0.20.3，故本地运行/构建不受影响。如需在本机离线复现，可重新下载 tarball 并改回 `file:` 形式。
- 组件 `src/views/tools/components/ExcelMergeTool.vue` 与 `PdfToExcelTool.vue` 本来就只用 `import * as XLSX from 'xlsx'` 的标准 API（read/sheet_to_json/book_new/aoa_to_sheet/write），0.20.3 完全兼容，无需改代码。
- 期间曾尝试改用 `exceljs`（registry 可用、无此漏洞），但用户明确要求回到 SheetJS 0.20.3，故已卸载 exceljs 并回退。
- 构建验证：`npm run build` 通过（268 modules）。
